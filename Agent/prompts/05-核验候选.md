# 调用 check_candidate · 训练前核验

使用 `{{上下文}}` 中的两组四项算子、冻结配方、训练样本引用、验证清单引用、目标硬件、资源上限和本阶段输出目录，向 `check_candidate` 发出请求。

1. 按 [SearchedNet 位置表](../README.md) 核验长度、顺序和候选集合。要求适配层把经白名单核验的算子名称构造成项目接受的 Genotype。若接口需要“权重、名称”元组，可统一使用 1.0 占位并注明来源；网络构建只读取名称。给有序的八项计算结构指纹。
2. 用本轮实参实例化 SearchedNet，逐层读回四个 down cell 和四个 up cell 的实际算子，核对方向、顺序、初始通道 16 和通道变化。打印最终生效的数据路径、验证清单和输出目录。现有入口依赖相对路径的 genotype 与写死的数据、输出位置；只有这些绑定实际生效才允许提交训练。输出目录必须与历史 NAS_29、Unet 和其他候选隔离。
3. 按计划 batch、体积、精度和设备用训练样本执行前向、掩膜内 L1、反向和一次优化。核验输入为 B×9×128×128×128、输出为 B×1×128×128×128、跳连拼接形状匹配、掩膜有效，记录损失及梯度的有限性、可训练参数数、设备峰值显存和单步时间。预检产生的权重不进入训练。
4. 返回 `candidate_check`、结构与绑定指纹、设备实测、通过状态和日志。区分形状不匹配、读取了错误 genotype、显存超限、数据故障。指出受影响的候选或共享配置。对共享配方的调整必须回到主控重新冻结并保证对照可比。

本次核验单位为结构、配方和阶段。用硬件快照对应的训练进程回读每个优化器参数组的初始学习率、weight decay、AMSGrad、全局 batch、加载线程/进程、精度及调度周期，逐项与请求比对。核对加载器实际患者集合，区分 B 的共享子集、B、F 和正式选定清单，核对实际病例号集合和预期排除项；核对每轮训练样本数为全局 batch × 500。多步预热后记录稳定吞吐、峰值资源与可用余量，测量验证推理耗时并折算完整验证开销。返回 pair_id、配方和清单指纹及预算估计。对被入口忽略的字段标记不支持，回到 11 去重或缩减网格。
