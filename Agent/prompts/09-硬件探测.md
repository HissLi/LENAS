# 调用 inspect_hardware · 确定本次作业可以使用的硬件

在实际执行训练的主机、容器和 Python 环境内调用 inspect_hardware。输入为 {{上下文}} 中的设备限制、输出卷、并发额度和时间预算。记录探测时间、主机标识、框架版本及可见设备映射。

1. 枚举 CPU 架构、进程可用核数和线程限制、可用 RAM、输出与缓存卷的剩余空间。逐卡报告设备名、后端、物理及进程内编号、总显存与当前可用显存；统一内存设备注明共享关系。读不到的字段标为未知。
2. 将“硬件存在”“框架可用”“仓库训练器已支持”“已通过实际试步”分别记录。仓库原生路径支持 CPU、CUDA 单卡和 CUDA DataParallel；MPS 等其他后端需要适配并通过 05 的 3D 算子与反向验证。不要把机器型号、历史日志或其他主机的显存当作本次测量。
3. 优先给出可用单设备和串行方案。多卡时列出独立作业的设备分配和并发内存预算；同一配对跨卡训练时记录全局 batch 与各卡分片。检查设备可分配性和训练窗口，提交前刷新动态资源。CPU 回退也应以测得的耗时核算可行性。
4. 返回 hardware_report、设备和运行环境指纹、可用资源、未知项、兼容后端、建议的预检配置与原因。实际批量、吞吐和显存峰值交给 05 测量。没有满足预算的训练路径时返回具体缺口。
