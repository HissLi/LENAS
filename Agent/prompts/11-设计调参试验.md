# 设计结构与训练参数的联合试验

读取 {{上下文}} 中的三个结构、hardware_report、训练与验证清单指纹、预算和训练器能力。输出一行一配对的 trial_matrix。搜索计划分两次冻结：先列出待核验的网格，再用 05 的实测数据确认预算与有效配方。两步都在读取本轮验证成绩之前完成。

1. 三个结构共用 Adam、AMSGrad、FP32、原数据增强、掩膜内 L1 和余弦调度。以 batch 2、学习率 3e−4、weight decay 3e−5 为参照。先用一张兼容设备、相同精度和完整 128³ 输入测三个结构。若 batch 2 在某结构上超限，尝试全组 batch 1；按实际核数、RAM 及数据等待时间确定加载进程数。冻结全局 batch、设备类型、数据流与种子，使同阶段优化步数和见过的样本数可比。
2. 在每个结构上交叉学习率 {1e−4, 3e−4} 与 weight decay {0, 3e−5}。仓库训练器的单参数组会写死 weight decay，学习率也未作为现有训练入口的命令行参数开放。要求工具绑定参数并从真实优化器参数组读回。若只能改学习率，冻结实际 weight decay，仅运行两个不同学习率；若两者都不能覆盖，报告缺少的参数绑定，不宣称完成调参。对有效配置做指纹去重。
3. 为每行分配 architecture_id、recipe_id、pair_id，列出八个算子引用、学习率、weight decay、全局 batch、精度、优化器及其余参数、调度与周期规则、设备、种子、子集和独立目录。记录此配方相对基准的改动及纳入原因。
4. 按实测每步时间、验证频率、每次验证耗时、设备数量和安全余量估算各阶段设备时与墙钟时。先预留前两对各 5,000 步全量复核和胜者 80,000 步训练，再安排每对 1,000 步子集初筛。预算紧张时先保留基准和仅改变学习率的第二组配方，覆盖全部三个结构；仍超上限则给出缺口与缩减协议，尊重运行者的硬上限。记录计划与实际消耗。
5. 写明冻结的排序和晋级规则、固定的验证清单、每 500 步验证一次、阶段内相同的检查点机会。实例级失败单列，临时资源错误只按原配置重试；替换参数必须新建配方编号。输出试验矩阵、预算、预检依据、退化网格原因和调度顺序。
