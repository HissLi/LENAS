# 剂量预测 Agent：联合选择 SearchedNet 结构与训练参数

Agent 在实际训练主机上探测可用资源，根据训练数据提出三个八位置结构，再让每个结构试用同一组训练参数。比较单位是一个 **结构 × 参数配方**。不同结构可以有不同的最佳学习率和正则化强度。最终从头训练时，锁定胜出的结构、有效参数和经过对照验证的训练患者清单。

## 1. 一次联合搜索如何运行

运行者提供数据、输出位置和可用预算，可限制设备、时长、并发数或搜索范围。下表是首轮默认方案，步数均指优化器更新次数。先预留正式训练、验证和检查点的开销，再根据实测吞吐核算搜索预算。

| 阶段 | 患者和任务 | 默认预算与输出 |
|---|---|---|
| 探测与设计 | 在训练进程所在环境核实 CPU、加速器、内存和存储；核验原始 200 名训练患者，形成合格训练池 B，并在读取验证分数前冻结可疑病例提案。以 NAS_29 为对照，再提出两个由训练证据支持的结构 | 基准配方用于资源预检，三个结构都进入联合试验 |

| 全训练集复核 | 晋级的两对各自在 B 的全部患者上重新初始化 | 每对 5,000 步，仅以本阶段验证结果决选 |

## 2. Agent 实际可以选择什么

每个 genotype 有 `down` 和 `up` 两个有序列表，每个列表四项。一个 cell 把预处理输出分成两路，主路依次经过前两个算子，旁路经过第三个算子，两路逐元素相加后经过第四个算子。四层编码器复用同一份 `down`，四层解码器复用同一份 `up`，各层各自训练权重。第三项只控制 cell 内部旁路，跨编码器和解码器的特征拼接固定。输入、输出通道分别为 9 和 1，初始通道为 16，深度和每个 cell 的位置数均为 4，`channel_change=True`。[网络实现](../RTDosePrediction/NAS_29/searched.py) · [训练入口](../RTDosePrediction/NAS_29/train.py)

| 位置 | 合法 component | NAS_29 的选择 |
|---|---|---|
| down[0]、down[1] | 每项独立选择 `identity`、`conv`、`dep_conv`、`dil_conv`、`se_conv` | `identity`、`dil_conv` |
| down[2] | `identity`、`none` | `none` |
| down[3] | `avg_pool`、`max_pool`、`down_conv`、`down_dep_conv`、`down_dil_conv`、`down_se_conv` | `down_dep_conv` |
| up[0]、up[1] | 与 down 主路相同，每项独立选择 | `dep_conv`、`dep_conv` |
| up[2] | `identity`、`none` | `none` |
| up[3] | `up_conv`、`up_dep_conv`、`up_dil_conv`、`up_se_conv`、`up_interpolate` | `up_interpolate` |

`dep_conv` 是逐通道卷积加逐点卷积，`dil_conv` 使用膨胀率 2，主路的 `se_conv` 对通道做 SE 加权。`up_interpolate` 先卷积再做两倍三线性插值。实现里的 `identity` 和 `none` 分别在权重运算处回传输入或置零，外层仍按实现执行归一化与激活。最终模型按算子名称构建；历史 genotype 元组中的首个数是搜索权重，Agent 无需估算它。[算子实现](../RTDosePrediction/NAS_29/prim_ops.py) · [NAS_29 原始配置](../RTDosePrediction/NAS_29/geno.py)

## 3. 工具处理哪些数据

| 数据范围 | 用途 | 输出给 Agent 的信息 |
|---|---|---|
| 训练患者 pt_1–pt_200 | 数据质检、解剖与剂量统计、预检、参数优化 | 训练清单指纹、统计证据、训练损失、资源实测 |
| 验证患者 pt_201–pt_240 | 按相同规则准备数据、选择检查点、比较结构、正式模型验证 | 验证清单指纹、逐患者剂量误差、有效结构数、两项汇总指标 |
| 测试患者 pt_241–pt_340 及既有测试报告 | 留给定型后的独立测试 | 整个 Agent 运行均关闭该数据入口 |

原始 CSV 位于 `provided-data`。数据工具按给定患者清单准备或复用 NIfTI，复核 CT、结构和剂量的共用坐标及体素间距。模型看到的九通道依次为加权合并的 PTV、七个危及器官（OAR）和 CT。参考剂量除以 70 作为标签，`possible_dose_mask` 决定哪些体素计入 L1。物理距离和剂量梯度在未增强的训练体积上计算，使用 mm 和 Gy。必须保留原始 ROI 是否缺失的记录，因为加载器会对缺文件补零。[转换脚本](../RTDosePrediction/DataPrepare/prepare_OpenKBP_C3D.py) · [数据加载器](../RTDosePrediction/DataLoader/dataloader_OpenKBP_C3D.py) · [损失函数](../RTDosePrediction/NAS_29/loss.py)

**统计如何影响结构。** 每项训练统计有一个证据编号。Agent 把最值得验证的现象写成单位置替换假设，其余位置继承对照。下面的例子说明决策方式，均需工具实测后才可用于提案。

| 若训练工具观察到 | 可检验的一次替换 | 用什么判断 |
|---|---|---|
| 小体积 OAR 边界附近存在陡峭剂量梯度，且有足够多病例支持 | 把 up[2] 从 `none` 换为 `identity`，检验保留 cell 输入特征能否改善局部还原 | 比较小 OAR 的 D0.1cc 误差，同时按全体验证 Dose score 排名 |
| 靶区与最近 OAR 的距离在病例间变化大 | 把 down[0] 从 `identity` 换为 `dil_conv`，检验扩大感受野的效果 | 检查验证 Dose score，以及按训练集预定义距离分组的误差 |
| 多种 OAR 的勾画覆盖率差异大 | 把 up[1] 从 `dep_conv` 换为 `se_conv`，检验不同通道的加权是否有益 | 比较有效结构上的 DVH 误差并报告覆盖率 |

短训练评价的是完整网络。一个变体同时改变多个位置时，无法把分差归到其中某一项；并列或预算有限时保留这种不确定性。对于缺少支持的槽位，沿用 NAS_29 并标明原因。已有 UNet 和 NAS_29 可提供同口径的验证背景；本轮短训练排序以同预算重训的 NAS_29 为对照。

### 怎样判定一个病例是否应退出训练

原始清单保留全部患者。工具检查可读性、剂量和掩膜的坐标、单位及重复病例；确认有问题后优先从源数据修复。无法修复的硬错误登记隔离，合格病例组成 B。搜索阶段一律使用 B 或其共享子集，因此不同结构和配方看到的是同一批可用病例。

在 B 上，工具用体积、间距和剂量梯度等患者级特征做 k-medoids 聚类，寻找相对同簇病例持续偏离的患者。只有在重复抽样中稳定出现、且能在源数据上找到另一项质量疑点的病例才进入试验性排除清单 E。罕见但可信的解剖结构应得到保留。默认提名上限是 B 的 5%，也允许一个都不提名。审计表保留每个患者的去留理由和筛选前后的结构覆盖率；筛选只改变加载器使用的清单。

正式训练前，固定胜出的网络与参数，以相同更新步数比较 B 与筛选池 F。采用 F 需要同时满足全体验证患者的配对 Dose 误差改善、DVH 未恶化且受保护亚组表现稳定。详细判据见 [13 验证筛选策略](prompts/13-验证筛选策略.md)。证据不足时使用 B；报告说明此次比较只能评价整个筛选策略。

## 4. 训练、决选和可复现性

每个候选独享运行目录，保存实际加载的八个算子、代码与数据指纹、有效训练配方、日志及检查点。现有训练脚本从当前目录读取 `best_genotype.pkl`，并写入固定的历史输出路径；转换脚本还会遍历三个划分。工具适配层必须绑定本轮患者清单、genotype、数据加载器、在线验证路径和新输出路径，并核对实际生效值。仅传入 batch size 和迭代数不足以完成这些绑定。[训练入口](../RTDosePrediction/NAS_29/train.py) · [在线验证](../RTDosePrediction/NAS_29/online_evaluation.py)

基准配方沿用 batch 2、FP32、掩膜内 L1、Adam（学习率 3×10⁻⁴、有效 weight decay 3×10⁻⁵、AMSGrad 开启）、原训练增强和逐步余弦退火至 10⁻⁷。默认搜索学习率 {1×10⁻⁴, 3×10⁻⁴} 和 weight decay {0, 3×10⁻⁵}。batch 和加载进程数依据本机预检确定，随后对同场试验固定。每 500 步用全部验证患者评分，取最低正值 Dose score 的检查点。原训练器记录该值的负数。各阶段余弦周期等于阶段步数。[优化器与检查点](../RTDosePrediction/NetworkTrainer/network_trainer.py)

每阶段按未舍入的 Dose score 升序排列，平局依次比较 DVH score、可训练参数量和稳定的配对编号。主指标单位均为 Gy。分别报告同一结构换配方以及同一配方换结构的结果，区分这两种比较所支持的结论。最终记录优化器实际参数、全局 batch、学习率曲线规则、精度和运行时环境。已有 UNet、NAS_29 的结果可作背景；联合搜索使用本轮验证记录。[评分实现](../RTDosePrediction/Evaluate/evaluate_openKBP.py)

## 5. 工具调用与恢复约定

下列字段是所有工具提示词的共同约定。运行时将 `{{上下文}}` 替换为当前阶段有权使用的字段及上一阶段回执。对语言模型只传清单引用、统计和证据摘要；大体积数据保留在工具侧。

| 记录 | 必填内容 |
|---|---|
| 请求 | `run_id`、工具名、输入产物引用及指纹、允许的患者清单、冻结协议、输出目录；训练相关请求另带结构编号、配方编号、配对编号、训练清单指纹、阶段和种子 |
| 回执 | 状态（成功、运行中、失败或阻塞）、实际参数、产物位置及指纹、已耗预算、诊断；异步作业另带 `job_id` 与最近完成步数 |
| 决策 | 引用的证据编号、具体数值或工具错误、行动、剩余预算、下一阶段；所有结构以固定顺序保存八项 |

主控以运行号、结构指纹、配方指纹、训练清单指纹、阶段和种子识别同一次训练。中断后先查询原作业；恢复时校验检查点、数据及配置。只有工具确认的产物才推进阶段。个别候选超显存或数值发散时记录失败，继续其余候选；划分泄漏、必要数据损坏或实际 genotype 与提案不一致时，先修复该阶段再训练。工具尚未接入、预算不足或无可比较候选时，返回已完成的工作、具体阻塞和恢复入口。
